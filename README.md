# Template for bulk 3pDGE RNA-Seq project work

Before starting, identify the species and data type. For these specific instructions, this is:

-   Species - Mouse
-   Type - 3pDGE

All work should be performed with VScode and make use of workspaces and, in the case of engaging, remote explorer. VScode should have the following extensions installed.

## Instructions

1)  Locate the researcher's directory in filesystem. This should be in a projects directory and have the naming convention:

    > kerberosID-FacultyLastName

    Where kerberosID is lowercase and faculty last name is capitalized, separated by a hyphen. The purpose of this convention is to facilitate parsing when doing space accounting.\
    If the researcher does not yet have a directory in projects, create it according to the convention.

    If the directory is being created for the first time, a symlink needs to be created in:

     `/net/bmc-pub15/data/bmc/public/BCC/`

    The link should used the researchers first name. Check if the user already has a link, if they do, include the host name.can be done with:\
    `cd /net/bmc-pub15/data/bmc/public/BCC/`

    `ln -s /net/bmc-lab3/data/bcc/projects/heaji-Yilmaz Heaji.lab3`

2)  Enter the researchers directory and clone the appropriate git repo

    `git clone https://github.com/KochInstitute-Bioinformatics/bulk_mm_3pDGE_template.git`

3)  Move the cloned repo directory to a project directory. The project directories should be named according to this naming convention:

    > BMC_ID-DataType

    Where BMC_ID is the BMC Project ID or, if sequenced elsewhere, some short identifier. The data type could be "RNASeq", "3pDGE", "scRNAseq", "spatialTX" etc. depending on the experiment. The purpose of strict adherence to this convention is to facilitate finding of projects, size accounting, type accounting and other administrative actions.

    `mv bulk_mm_3pDGE_template BMC_ID-DataType`

4)  Enter the project directory and detatch from git tracking by removing the .git directory

    `rm -rf .git`

    The project will eventually be tracked with git but this tracking will be under a new repo that will be created and populated in steps detailed below.

5)  Add the directory to the VScode workspace using "File–\>Add Folder to Workspace" and save workspace to file using "File–\>Save Workspace As...". This make it easier to resume an analysis after it has been closed.

6)  Enter the data directory and copy the fastq files from the BMC source or other locations. Only the fastq files are required. The BMC will store the default QC data for a substantial period of time and more extensive QC data will be generated by this processing. Considerations:

    -   It is possible that multiple flowcells have been run for the experiment. If this is the case, data need to be copied into separate directories named by flowcell inside the data director
    -   If fastq files have not been gzipped, they need to be before running the workflow. this can be done by running gzip or pigz.
    -   When finished, the data directory or subdirectories should only contain fastq.gz files. If pigz is used, source fastq files might need to be removed.

7)  Edit the samples.csv file for the nextflow run. Details about how this should look are available in the workflow documentation:

    -   <https://nf-co.re/rnaseq/3.21.0>
    -   For 3pDGE, the sequencing is single-end so fastq_2 is empty
    -   When the same samples are sequenced in multiple flowcells, use the same sample name in different lines, each pointing to different fastq files
    -   For sample values, use a simplified version of the BMC sample ID where the "DYY-" part is replaced with "d" and condition metadata is appended. This approach is helpful because these sample values become directories and column headers in processing and it can be valuable to have informative sample names during processing.
    -   Be sure to rename the BMC_ID.csv with the relevant BMC_ID

8)  Edit the nf-core_rnaseq_3.21.0.sh submission script. Value that need to be changes are:

    -   the mail-user value should be edited to your email address

    -   the input value should be set to the csv file created above.

    -   The BMC_ID should be used to name multiqc_title and outdir

    -   For 3pDGE processing, the deflines of reads contain a UMI. The way the workflow handles these UMI have changed in recent versions and something is not quite right about this approach but it was successful. This needs to be investigated more thoroughly. The change I made to get successful processing was to set umitools_umi_separator to ":" instead of the "u" I have used in the past.

9)  Submit the processing script to the bcc queue. Once the workflow successfully completes, remove the temp directories and move the slurm output into the processed directory. Moving the slurm output file to the run directory retains this processing infromation and keeps the project directory clean:

    `rm -rf .nextflow* work`

    `mv slurm* BMC_ID/`
